```bash

cd /opt/petweb
```

## 3. Как вносить изменения

### Вариант А — через git (основной)

1. Правишь файлы в `C:\Users\Chep\Desktop\PetWeb` (VS Code, Claude Code…).
2. Коммит и пуш в `main`:
   ```bash
   git add -A
   git commit -m "Что поменял"
   git push
   ```
3. GitHub Actions сам: проверит проект → соберёт `files.json` и `playlist.json` → выгрузит архив в `/opt/petweb` → запустит `scripts/deploy.sh`.
4. Статус — во вкладке **Actions** репозитория.

Для CI нужны секреты репозитория (*Settings → Secrets and variables → Actions*): `SSH_HOST`, `SSH_USERNAME` (`root`), `SSH_PRIVATE_KEY` (содержимое `~/.ssh/petweb_deploy`). Пароли в GitHub **не нужны** — они в `.env` на сервере.

### Вариант Б — прямо на сервере (code-server)

Открой https://code.chepykella.ru — VS Code сразу открывает каталог `/opt/petweb`. Править можно всё, включая `.env`.

⚠️ Что важно знать:
- **Следующий деплой из git перезапишет файлы, которые есть в репозитории.** Удачную правку перенеси в репозиторий (или сразу правь через git).
- **Деплой не трогает:** `.env`, `data/`, `code-server-config/`, а также файлы, которых нет в репозитории (например, музыку, скопированную в `html/music/`).
- В терминале code-server нет docker. Чтобы применить изменения, зайди по SSH (команды ниже).

Что после правки нужно перезапустить:

| Что поменял | Команда (в `/opt/petweb`) |
|-------------|---------------------------|
| `html/*` (сайт, Miki, музыка) | ничего — nginx отдаёт файлы сразу |
| новая страница в `html/miki/docs/` | `bash scripts/regen.sh` (или через CI) |
| `nginx/nginx.conf` | `docker compose up -d --force-recreate nginx` |
| `prometheus.yml` | `docker compose up -d --force-recreate prometheus` |
| `HomeLab/HomePage/*.yaml` | ничего — Homepage перечитывает сам (иногда `docker restart homepage`) |
| `.env` | `docker compose up -d` |
| `bot/*` | `docker compose up -d --build workdays-bot` |
| `docker-compose.yml` | `docker compose up -d` |

## 4. Музыка для плеера

Плеер на визитке скрыт: **Ctrl + Alt + M** или набрать на странице слово `music`.

**Куда класть:** `html/music/`. Форматы: `mp3`, `ogg`, `opus`, `m4a`, `aac`, `flac`, `wav`, `webm`. Имя файла `Исполнитель - Название.mp3` становится подписью, порядок — по алфавиту (удобно `01 - …`).

Способ 1 — сразу на сервер (быстро, репозиторий не раздувается):

```bash
scp -i ~/.ssh/petweb_deploy *.mp3 root@<SERVER>:/opt/petweb/html/music/
```

Или перетащи файлы в папку `html/music` в code-server. Новые треки появятся после обновления страницы: nginx сам отдаёт список файлов папки.

Способ 2 — через git: положи файлы в `html/music/` локально, закоммить и запушь. Подходит для пары треков: большие файлы раздувают репозиторий.

Удалить трек — просто удали файл.

## 6. Пароли — `.env`

Все пароли и токены — в `/opt/petweb/.env`. В репозитории лежит только шаблон `.env.example` с описанием каждой переменной.

Первичная настройка (или перенос на новый сервер):

```bash
cd /opt/petweb
cp .env.example .env
nano .env            # заполнить пароли
chmod 600 .env
docker compose up -d
```

| Переменная | Зачем |
|------------|-------|
| `GRAFANA_ADMIN_PASSWORD` | пароль admin в Grafana и для виджета на Homepage. Grafana применяет его только при первом запуске — если поменял, смени и в интерфейсе Grafana |
| `CODE_SERVER_PASSWORD` | вход в code-server |
| `BOT_TOKEN`, `BOT_ADMIN_IDS` | Telegram-бот |
| `PORTAINER_API_KEY`, `PROXMOX_API_*`, `TRUENAS_API_KEY` | необязательные виджеты Homepage |

**Не коммить `.env`** — он в `.gitignore`. Бэкап держи отдельно (например, в менеджере паролей).

## 7. SSL

Сертификат выпускается вручную, CI его не трогает:

```bash
cd /opt/petweb
./cert.sh                       # certbot покажет TXT-записи _acme-challenge
# добавь их в DNS Selectel, подожди 1–2 минуты, нажми Enter
docker compose restart nginx
```

Сертификат живёт 90 дней — повторяй заранее. Пока сертификата нет, nginx работает на самоподписанном (браузер предупреждает).

## 8. Homepage (home.chepykella.ru)

Конфиги — `HomeLab/HomePage/`:

| Файл | Что там |
|------|---------|
| `services.yaml` | карточки сервисов: **Мониторинг** (CPU, RAM, диск, температура, сеть, nginx через Prometheus), PetWeb, HomeLab, VDS |
| `widgets.yaml` | шапка: ресурсы сервера, дата, погода, поиск |
| `bookmarks.yaml` | закладки, включая блок **Нейросети** |
| `docker.yaml` | подключение к Docker — статусы и нагрузка контейнеров |
| `settings.yaml` | тема, порядок и колонки групп |

Как включить виджеты Portainer / Proxmox / TrueNAS: создай API-ключ, впиши его в `.env`, раскомментируй блок `widget:` у сервиса в `services.yaml`, затем `docker compose up -d homepage`.

## 9. Частые команды

```bash
cd /opt/petweb
docker compose ps                         # что запущено
docker compose logs -f --tail=100 nginx   # логи сервиса
docker compose up -d                      # применить compose / .env
docker compose restart homepage           # перезапустить один сервис
bash scripts/deploy.sh                    # полный деплой вручную (как в CI)
bash scripts/regen.sh                     # обновить дерево Miki и плейлист
docker exec nginx nginx -t                # проверить конфиг nginx
df -h /; free -h                          # место и память
```

## 10. Если что-то сломалось

| Симптом | Что делать |
|---------|-----------|
| Сайт отдаёт 403/404 | `docker compose up -d --force-recreate nginx`; проверь, что файлы есть в `/opt/petweb/html` |
| Браузер ругается на сертификат | выпусти настоящий: `./cert.sh` (раздел 7) |
| `docker compose` пишет «required variable … is missing» | не заполнен `.env` (раздел 6) |
| Деплой в Actions падает на SSH | проверь секреты `SSH_*` |
| На Homepage виджет Grafana с ошибкой | пароль в `.env` не совпадает с паролем в Grafana |
| Бот не отвечает | `docker logs workdays-bot`; задан ли `BOT_TOKEN` |
| Трек не играет | формат из списка раздела 4? имя файла без `/`? |
